2-1. calculator.py — 서비스가 PLUS(+ ) 만 구현된 미완성 코드 수정 완료

ArithmeticOperator.srv에는 PLUS / MINUS / MULTIPLY / DIVISION 4개 연산자 상수가 정의되어 있는데, on_operator 콜백은 PLUS만 처리하고 그 외 연산자는 무시(응답 없음)하는 문제가 있었습니다.

수정 내용: 4칙연산을 모두 처리하고, 미지의 연산자는 로그 경고 후 0.0으로 응답하도록 완성했습니다. (0으로 나누기 방지 포함)

  def on_operator(self, req, res):
    a, b = self.argument_a, self.argument_b
    op = req.arithmetic_operator
    if op == ArithmeticOperator.Request.PLUS:
      result = a + b
    elif op == ArithmeticOperator.Request.MINUS:
      result = a - b
    elif op == ArithmeticOperator.Request.MULTIPLY:
      result = a * b
    elif op == ArithmeticOperator.Request.DIVISION:
      result = a / b if b != 0.0 else 0.0
    else:
      self.get_logger().warn(f'알 수 없는 연산자: {op}')
      res.arithmetic_result = 0.0
      return res
    res.arithmetic_result = result
    self.argument_result = result
    self.get_logger().info(
        f'연산 대상 숫자: {a} {b} ====== 연산 결과: {self.argument_result}'
    )
    return res

2-2. calculator.py — 액션 서버 무한 루프 위험 수정 완료

on_check는 argument_result(누적할 값)를 계속 더해 목표 임계값(goal_sum)을 넘기기를 기다립니다. 그런데 연산이 한 번도 수행되지 않아 argument_result == 0이면 total이 영원히 0을 넘지 못해 무한 반복됩니다.

수정 내용: 누적값이 0 이하이면 즉시 goal을 abort하고 종료하도록 방어 코드를 추가했습니다.

    goal_sum = goal_handle.request.goal_sum
    argument_result = self.argument_result
    # 누적할 값이 0 이하이면 무한 루프에 빠지므로 중단
    if argument_result <= 0.0:
      self.get_logger().warn('누적할 연산 결과가 없어 목표를 달성할 수 없습니다')
      goal_handle.abort()
      result = ArithmeticChecker.Result()
      result.total_sum = 0.0
      return result

2-3. argument.py — 런타임 파라미터 변경 미반영 버그 수정 완료

코드 주석의 의도는 "실행 중인 노드를 중단하지 않고 값을 변경"하는 것입니다. 그러나 __init__에서 읽은 min_random_num / max_random_num을 멤버 변수에 캐시해 두고 on_timer가 그 캐시 값을 사용해서, ros2 param set으로 값을 바꿔도 발행 결과에 전혀 반영되지 않는 문제가 있었습니다.

수정 내용: on_timer에서 파라미터를 매 호출마다 조회하도록 하고, on_set 검증도 변경 요청값을 반영해 min ≤ max인지 검사하도록 개선했습니다. (미사용 멤버 변수 제거)

  def on_timer(self):  # 2개 숫자 만들기(random), msg 만들기, pub, logger
    # 파라미터를 매번 조회해 런타임 변경 사항이 즉시 반영되도록 함
    low = self.get_parameter('min_random_num').value
    high = self.get_parameter('max_random_num').value
    msg = ArithmeticArgument()
    msg.argument_a = float(random.randint(low, high))
    msg.argument_b = float(random.randint(low, high))

    self.pub.publish(msg)
    self.get_logger().info(f'발행: a={msg.argument_a}, b={msg.argument_b}')

  def on_set(self, params):
    low = self.get_parameter('min_random_num').value
    high = self.get_parameter('max_random_num').value
    for p in params:
        if p.name == 'min_random_num':
            low = p.value
        elif p.name == 'max_random_num':
            high = p.value
    if low > high:
        return SetParametersResult(successful=False, reason='잘못된 값')
    return SetParametersResult(successful=True)

2-5. launch/my.launch.py — 실행 파일 미지정 미완성 완성됨

기존 파일은 executable=''로 실행 노드가 지정되지 않은 빈 껍데기였습니다. 현재 argument(랜덤 숫자 발행)와 calculator(수신·연산·액션)를 함께 띄우는 형태로 완성되어 있으며, 실제로 두 노드가 통신하는 것을 확인했습니다.

from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    return LaunchDescription([
        Node(
            package='my_py_pkg',
            executable='argument',
        ),
        Node(
            package='my_py_pkg',
            executable='calculator',
        ),
    ])
